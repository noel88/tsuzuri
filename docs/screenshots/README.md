# 화면 캡처

`tools/screens/shoot.py`로 만든다. 실제 바이너리를 가상 터미널(pty)에서
돌리고 입력을 넣은 순간의 출력을 포메라 DM250 해상도로 옮긴 것이다.
손으로 그린 목업이 아니다.

```bash
python3 tools/screens/shoot.py
```

| 파일 | 화면 |
|---|---|
| `01-menu.png` | 초기화면 — 번호로 이동하는 PC통신 양식 |
| `02-problem.png` | 출제 — 답을 입력하는 중 |
| `03-result.png` | 결과 — 빠진 표현, な형용사 활용 오류, 문체 불일치를 짚음 |
| `04-result-quiet.png` | 결과 — 짚을 게 없으면 조용하다 |
| `05-review.png` | 첨삭 — 오류(✗)와 뉘앙스(·)를 구분 |
| `06-setup.png` | 설정 — API 키 보관 경고 |

`dark/`는 fbterm 기본에 가까운 어두운 화면, `paper/`는 종이 느낌이다.
가로 3072px (1024px의 3배). 세로는 화면마다 다르다 — 아래 참고.

## 사용할 때 밝혀 둘 것

- **실기 사진이 아니다.** 다만 칸 수는 실기에서 잰 값이다(2026-09-17,
  `stty` 36 128). 포메라 fbterm은 1024×600 화면에 **128×36칸**, 즉 8×16
  글꼴을 쓴다. 글꼴 자체는 맥의 D2Coding + 히라기노 각고딕으로 그렸다.
  실제 기기 화면을 원하면 `deploy/README.md`의 실기 캡처 절차를 쓴다.
- **세로는 화면이 쓴 만큼만 잘랐다.** 기기 화면은 36줄인데 한 화면의 내용은
  20줄 남짓이다. 실제 터미널에서는 그 아래에 이전 화면의 끝부분이 남아
  있지만, 캡처는 화면 단위로 담으므로 빈 줄을 걷어냈다.
- **`05-review.png`의 첨삭 내용은 예시 데이터다.** 화면을 보여주기 위해
  넣은 것이고 실제 API 응답이 아니다. `03`, `04`의 분석 결과는 실제
  분석 엔진이 낸 것이다.
- 앱은 화면을 지우지 않고 이어서 출력한다. 캡처는 화면 하나 단위로 잘랐으므로,
  실제 터미널에서는 위쪽에 이전 화면의 끝부분이 보인다.
